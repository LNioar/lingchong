# DeskPet 产品使用说明书

更新日期：2026-10-22。本文以当前源码实现为准；新功能需要重新编译、安装对应平台程序后生效，不表示已经发布了新的 MSI 或 APK。

## 1. 产品定位与当前能力

DeskPet 从已启用的平台采集热点，结合用户兴趣选择内容，通过模型生成宠物口吻的回复。没有配置模型 API Key 时，可以使用本地模板展示真实热点；热点采集仍需联网。

| 功能 | Windows 桌面版 | Android 当前版本 |
| --- | --- | --- |
| 宠物界面 | 透明置顶小窗口，可拖动，支持托盘 | 前台全屏应用，不是悬浮在其他应用上的桌宠 |
| 双击召唤 | 双击宠物，联网刷新热点 | 连续双击宠物，联网刷新热点 |
| 气泡 | 独立窗口，正文内部滚动，底部按钮固定 | 宠物下方的页面内气泡，仅气泡内部滚动 |
| 宠物动画 | idle / happy / curious / excited / sleepy / bored 六种 | 同左 |
| 设置入口 | 右键托盘 →「设置」 | 页面右上角「设置」 |
| 设置范围 | 常规、宠物、模型、采集、语音、用户画像 | 模型与宠物画像；暂未提供完整采集、语音及用户画像编辑界面 |
| 用户反馈 | 喜欢、不感兴趣、关闭、查看原文 | 喜欢、不感兴趣、关闭；暂没有「查看原文」按钮 |
| 自动播报 | 已实现，受策略与采集结果影响 | 应用运行时有自动播报逻辑，不保证退到后台后持续工作 |
| 语音 | 外部工具基础实现，部分入口调用 | 尚未接入可用的原生语音方案 |

“播报”在本文中默认指生成并显示热点文案，不等于一定发出声音。语音的当前限制见第 8 节。

## 2. 安装与首次使用

### Windows

使用实际提供的 Windows GUI 安装包或 GUI 构建产物。文件同样叫 `deskpet-app.exe`，但没有启用 `tauri` feature 的构建是后台模式，不显示宠物。

启动 GUI 版本后，桌面显示宠物，系统托盘显示 DeskPet 图标。窗口无法启动时，检查 WebView2 运行环境，并参见 [Windows 指南](windows-guide.md)。本文不提供尚未生成的安装包下载地址。

### Android

安装当前项目编译出的 APK 并启动。应用隐藏状态栏与底部导航栏，边缘滑动可以临时呼出系统栏。页面保持固定，长气泡在内部滚动；设置弹窗有自己的滚动区域。

修改源码不会直接更新已安装应用。需要重新编译并安装 APK；覆盖安装且包名、签名兼容时通常保留应用数据，不要为了更新而先卸载或清除数据。

### 首次体验

1. 连接网络，启动程序，等待热点采集。首次启动没有历史数据，自动采集可能需要一段时间。
2. 在设置中填写模型服务，也可以先不配置 Key 使用基础模板模式。
3. 配置宠物名称、性格、表达偏好与背景设定。
4. 双击宠物，等待联网刷新结果；对感兴趣的内容点击「喜欢」。

## 3. 日常操作

### 双击联网刷新

双击立即显示「正在联网刷新热点……」，并行请求已启用的采集平台。它跳过本地定时采集冷却，从本次网络请求实际返回的内容中选择尚未播报的热点，也会排除近期标记为不感兴趣的条目。

- 单个采集源最多等待约 20 秒；刷新与回复生成的完整流程最多等待约 45 秒。
- 刷新失败会提示失败，不使用上次消息作为兜底。
- 请求成功但没有未播报候选时，显示「本次刷新暂无未播报的新热点」。联网刷新不保证网站每次都有新内容。
- 请求尚未完成时，重复双击不会重复提交同一个页面的请求。
- 已播报热点按 ID 记录到本地数据库，重启后仍参与去重；这不等于同一事件跨平台绝对只出现一次。
- 手动召唤跳过勿扰与自动播报评分门槛；自动播报仍遵守相关策略。

### Windows 操作

| 操作 | 行为 |
| --- | --- |
| 按住宠物拖动 | 移动桌宠窗口 |
| 双击宠物 | 本次联网刷新与回复 |
| 在宠物上滚动滚轮 | 切换动画情绪 |
| 左键单击托盘图标 | 显示或隐藏宠物 |
| 右键托盘 →「显示宠物 / 隐藏宠物」 | 控制宠物窗口 |
| 右键托盘 →「设置」 | 打开或前置设置窗口，关闭设置只隐藏该窗口 |
| 右键托盘 →「退出」 | 完全退出程序 |

注意：当前托盘「立即播报」仍读取本地近 24 小时候选，并尝试语音，尚未统一为双击的实时刷新流程。需要立刻联网更新时请双击宠物。

Windows 气泡的标题、正文和原文链接可以内部上下滚动，也可点击内容区域后用键盘滚动。底部反馈按钮保持可见。没有交互时约 15 秒自动隐藏；鼠标停留或键盘焦点在气泡内时暂停自动隐藏，离开后重新计时。

### Android 操作

双击宠物触发刷新，已移除「聊一条热点」按钮。主页面不能上下滚动，长内容只在气泡内滚动，右上角打开设置。宠物区域不显示蓝色触摸高亮。

播报或反馈带来的临时情绪通常持续 8 秒后回到 idle；关闭页面内气泡、请求失败或没有新候选时会恢复 idle。修改宠物画像不会更换当前的切片图或创建新的动画形象。

## 4. 配置模型服务

| 字段 | 填写方法 |
| --- | --- |
| API 地址 | 服务商提供的兼容 OpenAI 的接口基地址，通常以 `/v1` 结尾，具体按服务商要求填写 |
| API Key | 对应服务商的密钥 |
| 模型名称 | 服务商提供的实际模型标识 |
| 向量模型（可选） | 服务商支持 embeddings 接口时填写；不支持或不需要时留空 |

保存后用于后续模型请求，无需重启。旧的、已经开始的请求不会因为修改设置而重新生成。

密钥输入框不会回显已保存的密钥，只显示配置状态。留空保存会保留原密钥；输入新值会替换；勾选「清除已保存的 API Key」并保存才会清除。清空向量模型后保存，重新打开仍应为空。

未配置 Key 时不请求对话模型，使用真实热点的模板文案；没有热点时不会编造新闻。向量模型不可用时使用占位向量，不能视为真实语义理解。未配置模型时，宠物性格不会通过生成式回复充分体现。

当前没有内置模型连通性测试按钮，保存成功只代表配置已保存和应用，不代表服务商鉴权、额度或模型能力验证通过。

## 5. 宠物画像与用户画像

### 宠物画像：定义宠物是谁

Windows 设置 →「宠物」；Android 设置 →「模型与宠物设置」。可配置：

- 名称：不能为空，最多 80 个字符。
- 性格：宠物的性格特点。
- 表达偏好：希望的语气和表达习惯。
- 背景设定：身份、经历或世界观，可留空。

后三项单项最多 4000 个字符。保存后，下一次模型回复会读取宠物画像，结合用户画像自由表达，不套用指定回复示例或固定句式。该设置影响文本生成，不改变动画资源和 TTS 音色。

### 用户画像：定义主人关注什么

Windows 设置 →「用户画像」可以编辑人物描述、兴趣主题与权重。主题不能为空或重复，权重范围为 0～1。Android 当前通过热点反馈间接学习兴趣，暂未提供完整画像编辑界面。

| 反馈 | 当前作用 |
| --- | --- |
| 喜欢 | 增加该热点标签对应的兴趣权重 |
| 不感兴趣 | 降低兴趣权重，并在近期候选中排除该热点 |
| 关闭 | 记录较弱的负向反馈；没有热点 ID 的状态提示不记录反馈 |
| 查看原文（Windows） | 记录点击反馈并用系统浏览器打开原文 |
| 气泡自动隐藏（Windows） | 对有真实热点 ID 的内容记录忽略反馈 |

缺少标签的热点无法有效调整对应主题。每日维护任务在应用持续运行且触发时执行权重衰减和过期数据清理；不要将其理解为关闭应用后也会执行的系统定时任务。

## 6. Windows 完整设置与生效范围

| 设置 | 当前生效方式 |
| --- | --- |
| 模型服务、向量模型、宠物画像 | 保存后更新运行时，用于后续回复 |
| 勿扰时段、播报阈值 | 保存后更新运行时；手动双击不受自动播报门槛限制 |
| 播报间隔、平台采集间隔 | 更新后在后续循环读取，已经开始的等待可能仍按旧间隔结束 |
| 平台启用开关 | 控制后续定时及手动采集，不取消已发出的请求 |
| RSSHub 地址 | 需要重启 |
| 语音启用与音色 | 需要重启，且仍受外部依赖限制 |

默认勿扰时段为 23:00～次日 08:00，最小主动播报间隔为 45 分钟。有用户兴趣时默认评分门槛为 0.6；无兴趣画像使用较低的冷启动门槛。

已知限制：启动时调度器打扰策略尚未完整同步磁盘自定义值，可能先使用默认策略。若需确认自定义勿扰策略已应用，启动后在 Windows 设置中重新保存一次。该问题列入后续修复计划，不应依赖它进行严格的勿扰保障。

## 7. 自动播报与联网范围

当前提供知乎、哔哩哔哩、微博及 RSSHub 相关采集，抖音、小红书依赖 RSSHub 路由。平台反爬、限流、RSSHub 可用性及网络环境都会影响结果，不保证全部平台始终可用。

应用启动后会进行初始采集，然后运行自动播报与定时采集。自动播报没有合适候选时保持安静。Android 当前应作为前台应用使用，没有完成后台常驻服务、桌面悬浮窗、开机启动和后台持续播报。

模型请求会使用热点信息及设置中的宠物、用户画像；启用向量模型后会请求相关标题或兴趣主题的向量。模板模式不发送对话模型请求，但热点采集本身仍会访问网络。

## 8. 语音功能的真实状态

当前是基础实现，不是已完成的跨平台语音产品。

| 项目 | 当前状态 |
| --- | --- |
| 合成方式 | Rust 调用外部 `edge-tts` 命令生成临时 MP3 |
| 播放方式 | 查找外部 `mpv`、`ffplay` 或 `cvlc` 播放器 |
| Windows 依赖 | 合成工具、播放器及其运行环境需另外准备，未随程序自动交付 |
| Android | 没有接入 Android 原生 TTS，不能按现有桌面外部命令方案正常使用 |
| 双击刷新 | 当前只显示气泡，没有调用语音 |
| 自动播报 / Windows 托盘「立即播报」 / headless | 已有语音调用，但能否出声取决于依赖、网络和音频环境 |
| 开关与音色 | 已有配置，重启应用后生效 |
| 试听、停止、播放状态、队列 | 尚未提供完整产品能力 |

当前自动播报与 Windows 托盘路径会先等待语音尝试，再显示气泡；依赖或服务较慢时可能拖延文本出现。后续计划改为先显示文案，再异步播放。

因此，仅打开「启用语音播报」不会自动补齐依赖。没有声音时先按上述能力边界判断，不必反复修改模型 API Key；模型回复和语音合成是不同模块。

## 9. 数据保存、更新与备份

Windows 数据目录通常为 `%APPDATA%\deskpet\`；Android 使用系统分配的应用私有数据目录，不建议依赖普通文件管理器直接修改。

| 文件 | 内容 |
| --- | --- |
| `config.toml` | 常规、模型、宠物画像、采集、语音配置，包含 API Key |
| `deskpet.db` | 热点、用户画像、反馈、采集日志及已播报记录 |
| `deskpet.log` 及轮转备份 | 运行和故障日志 |

API Key 存在本机配置文件中，目前没有系统凭据加密存储。日志可能包含模型请求/响应、热点和画像相关信息，分享前检查并移除私人内容。

Windows 备份前先退出应用，再复制配置与数据库；恢复时同样退出应用，保留当前文件副本后再恢复。Android 暂未提供应用内导入导出。更换电脑不会自动同步数据。

覆盖安装通常不等于重置设置；卸载、清除应用数据或删除数据目录可能丢失密钥、画像和已播报记录。新默认值也不一定覆盖用户已保存的值。

## 10. 常见问题

| 问题 | 检查方法 |
| --- | --- |
| 双击后没有新消息 | 检查网络、是否启用采集平台；网站可能没有新内容，当前候选也可能已播报或被排除 |
| 刷新失败 | 按提示检查采集源；失败不会回退旧热点，模型调用也可能超时 |
| 模型没配置还能用吗 | 可以用模板展示已采集的真实热点；不能离线生成实时新闻 |
| 没有声音 | 先看第 8 节，双击和 Android 原生语音尚未接通 |
| 画像改了但回复没变 | 确认保存成功且配置了可用模型；已显示的回复不会重新生成 |
| 设置向量模型为空又显示默认值 | 当前源码已修复；确认运行的是重新编译的版本，并已保存设置 |
| Windows 修改后 Android 没更新 | 确认两台电脑代码已同步，重新编译并覆盖安装 APK |
| Windows 找不到设置 | 右键系统托盘图标；确认使用启用了 `tauri` 的 GUI 构建 |
| Android 页面加载失败 | 当前资源内置 APK；先确认安装的是新版本，再看 [Android 构建排障](android-studio.md) |
