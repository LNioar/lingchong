# 语音输出实施计划

更新日期：2026-10-24。本文是待实施计划，优先满足 Android 屏幕头部实体桌宠，再补齐 Windows。工期为单人开发估算，按工作日计算，不包含目标设备或语音引擎不可用造成的等待。

Windows 专项选型已调整为 Edge TTS 在线合成与 mpv 播放，详细结构、依赖打包和实施工期以 [Windows Edge TTS 设计方案](edge-tts-windows-design.md) 为准。下表保留跨平台总体顺序，原 Windows 原生语音方案不再作为当前首版方案。

## 当前基础

- `crates/deskpet-tts/src/lib.rs` 已有 `TtsProvider::speak`，尚无停止、引擎状态和音色枚举接口。
- `edge_tts.rs` 依赖外部 `edge-tts` 与播放器，不适合作为 Android 的语音实现。
- `runtime.rs` 当前只记录播放错误，`tts_speak` 未将实际失败完整反馈到界面；找不到播放器时，现有提供方仍可能返回成功。
- `gui.rs` 自动播报和 Windows 托盘入口先等待语音再显示气泡；`ipc.rs` 双击刷新只显示气泡，未接入朗读。
- Android 目前只有模型与宠物画像设置，需增加语音设置。隐藏的“听点新鲜事”按钮继续保持隐藏。

## 计划表

| 顺序 | 阶段 | 主要工作 | 预计工作日 | 验收标准 |
| --- | --- | --- | --- | --- |
| 1 | 目标设备验证 | 检查实体桌宠 Android 板的音频输出、系统 TTS 引擎、中文语音数据及可用音色 | 0.5 | 目标设备可以播放中文测试句；明确联网与离线能力 |
| 2 | 统一语音调度 | 在现有 TTS 层补播放、停止、状态与错误反馈；每次播放携带任务 ID；先展示气泡，再异步朗读 | 1～1.5 | 引擎失败不阻塞气泡，不再把失败报告为播放成功 |
| 3 | Android 原生接入 | 通过 Tauri Android 插件桥接系统 TextToSpeech，管理异步初始化、播放回调、音频焦点、停止与释放 | 1.5～2.5 | 目标设备真实出声；没有引擎或中文数据时给出明确提示 |
| 4 | 接通业务与控制 | 双击热点刷新、自动播报共用语音入口；气泡提供停止和重播；单路播放、取消旧任务、过滤链接与状态提示 | 1～1.5 | 每条成功回复只朗读一次；连续触发不重叠；关闭气泡停止对应朗读 |
| 5 | 语音设置 | Android 增加启用开关、音色、语速、音量与试听；扩展配置结构和后端校验，兼容旧配置并支持即时应用 | 1～1.5 | 设置保存、重启保留、试听和关闭语音均符合预期 |
| 6 | Android 验收交付 | 测试缺引擎、断网、长文本、取消、快速双击、音频焦点变化、前后台切换；构建 APK 并在目标硬件验收 | 1～1.5 | 新安装与覆盖升级可用，前台连续播报稳定，退出后无残留声音 |
| 7 | Windows Edge TTS | 在线合成、mpv 播放、统一控制与设置，随包交付运行时 | 5～8 | 无预装 Python/mpv 的机器可播放；断网保留文字并提示语音失败 |

阶段 1～6 顺序推进，Android 首版预计约 6～9 个工作日；Windows Edge TTS 专项预计约 5～8 个工作日。若顺序完成两端，总计约 11～17 个工作日，实际复用范围以实施为准。首个 Android 里程碑为阶段 3 的目标设备实际出声，阶段 6 才是可验收的 Android 语音版本。

## 首版行为约定

- 朗读模型回复或真实热点的模板文案，不朗读刷新中、错误、无新热点等状态提示。未配置对话模型不影响模板文案朗读。
- 先出现文字，再开始朗读；失败时保留文字并显示可理解的原因，不自动无限重试。
- 手动新请求优先于自动播报，并取消旧朗读；播报中不叠加自动语音，也不积压过时内容。
- 点击停止、关闭对应气泡、关闭语音或退出应用，结束当前朗读并取消待播放任务；关闭气泡保留原有反馈语义。
- Android 进入后台时停止语音，返回前台不自动重播；首版按实体桌宠前台常驻方式验收。后台持续播报另行设计。
- 播放状态与既有情绪恢复计时统一处理，避免读到一半被旧计时器改变状态。
- 离线播报取决于目标设备的引擎与语音数据。阶段 1 必须先验证，不承诺所有 Android 设备都自带可用中文语音。
- 音色设置与宠物画像独立；不增加麦克风权限，语音输入和唤醒词不在本次输出功能范围。
