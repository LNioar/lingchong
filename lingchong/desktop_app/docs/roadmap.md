# DeskPet 未来扩展计划

更新日期：2026-10-22。本文是拟实施计划，不代表下列能力已经上线，也不承诺完成日期。当前使用方法与限制以 [产品使用说明书](user-manual.md) 为准。

## 1. 当前基线

已实现 Windows 桌宠、托盘设置、可滚动气泡；Android 前台全屏、双击交互与页面内气泡；双击联网刷新、按热点 ID 持久化去重、模型/模板回复、用户兴趣反馈、宠物画像及部分配置热更新。

语音已有接口和外部命令方案，但 Windows 依赖未自动交付、Android 原生实现缺失、双击未接入语音。Android 也没有完整后台运行或悬浮桌宠能力。现有测试通过不等于已完成新安装包交付和两端实机验收。

## 2. 建议实施顺序

| 阶段 | 优先级 | 工作重点 | 完成标准 |
| --- | --- | --- | --- |
| A：行为与交付一致 | P0 | 初始化策略、统一入口、错误反馈、稳定打包 | 同一设置重启前后行为一致，干净环境可安装运行 |
| B：可用语音闭环 | P1 | Windows/Android 播放能力、双击接入、停止与试听 | 有可用引擎时可播报，无引擎或失败时明确降级 |
| C：设置与信息质量 | P1 | Android 设置补齐、连通性诊断、跨源去重 | 用户可以自行定位配置问题，重复事件减少 |
| D：后台与陪伴能力 | P2 | Android 后台方案评估、历史记录、互动扩展 | 功耗、生命周期及用户控制满足验收 |
| E：数据与生态 | P2 | 导入导出、多宠物资源、可选同步 | 数据可迁移、资源可校验，默认本地优先 |

阶段内先做可独立验收的小版本，不将语音、后台常驻和资源生态捆绑为一次发布。

## 3. 阶段 A：修复现有行为差异

### A1. 调度与配置一致性

- 应用启动时完整应用磁盘中的勿扰、最小间隔和阈值，不依赖再次保存设置。
- 播报/采集间隔变更后可唤醒正在等待的循环，减少“已保存但旧等待还没结束”的困惑。
- 明确平台禁用与 RSSHub 聚合/回退的关系，避免关闭某个平台后仍经聚合路由获取同类内容。
- 保存配置与画像时提供准确的部分成功状态，后续考虑统一提交与回滚策略。

验收：自定义跨夜勿扰保存并重启后仍生效；禁用平台不再新增其请求；更改间隔后无需重启就能按约定生效。

### A2. 统一主动触发入口

- 将 Windows 托盘「立即播报」与双击统一为实时刷新入口，同时保持自动播报走调度策略。
- 统一请求编号、取消、重复触发保护及气泡状态，过期请求不能覆盖新结果。
- 降低少量慢采集源对整体响应的影响；部分来源可用时先利用成功结果，错误保留可查看的摘要。

验收：各手动入口都实际发起刷新；失败不复用旧文案；连点不堆积请求；断网、空结果、模型失败有区别清楚的反馈。

### A3. 安装包与回归流程

- 建立 Windows MSI 与 Android APK 的可重复构建流程，校验签名、版本和所需资源。
- 对 WiX、Rust、JDK、SDK/NDK 等构建依赖提供检测与缓存说明，减少人工机器差异。
- 增加全新安装、保留数据升级、旧配置迁移、旧数据库迁移和长气泡交互回归。
- 保留源码验证、模拟测试和实际设备验证的区别，发布说明列出平台与已知问题。

验收：干净 Windows 环境和 Android 实机均可安装启动；升级不清空密钥和画像；安装包确实包含本版本前端资源。

## 4. 阶段 B：语音功能实现

### B1. 统一语音接口与触发流程

现有 `TtsProvider::speak` 仅表示“尝试合成并播放”，不足以表达完整的用户操作。计划补充：

- 引擎初始化/可用性检测、音色枚举、试听、播放、停止和释放。
- 就绪、合成中、播放中、完成、失败等可观察状态，失败返回前端，不再仅记日志或仍报告成功。
- 文本生成后先显示气泡，再异步处理语音；网络合成或播放不得阻塞气泡出现。
- 双击、托盘、自动播报共用同一语音入口；刷新状态、错误提示、没有新热点等状态消息默认不朗读。
- 朗读前处理链接和 Markdown 等非口语内容，原文链接保留在气泡中。

验收：双击出现新热点时，开关开启则触发一次语音，关闭则不触发；语音失败不影响正文显示；状态能区分“没有引擎”和“网络合成失败”。

### B2. Windows 播放能力

首个目标是提供无需用户额外安装 Python 与独立播放器的默认语音路径。计划评估 Windows 本机语音引擎作为默认方案，在线合成作为可选方案；最终选型以音色、离线可用性、分发和实际机器验证结果为准。

- 通过平台适配层访问可用音色，使用应用内播放能力或平台播放能力，不依赖随机存在的播放器。
- 当前 `edge-tts` CLI 保留为兼容/可选路径，先补依赖检测和明确错误，不把它当作已内置能力。
- 音色、语速、音量在界面可配置，优先支持立即应用。
- 选择的音色不可用时提示并提供可用选项，不能静默显示“播放成功”。

验收：没有 Python、mpv、ffplay、VLC 的测试机上，存在可用默认引擎和音色时可正常播报；没有可用引擎时有明确文本降级。

### B3. Android 原生 TTS

计划通过 Android 平台桥接接入系统 TTS，不在 Android 中启动桌面 `edge-tts` 或播放器进程。

- 管理引擎异步初始化、语言/音色检查、播放进度和错误回调。
- 处理 Activity 暂停、恢复、退出和引擎释放，避免退出后继续朗读或重复初始化。
- 提供可用音色选择、试听、停止以及缺少语音数据的提示。
- 首阶段只保证明确的前台行为；后台持续播报属于后续独立能力，不因接入 TTS 就视为已完成。

验收：实机双击产生新热点后可朗读；停止立即生效；切后台、返回前台、旋转和退出不重复播放；离线能力根据设备引擎与语音数据实际验证，不能保证所有机型离线可用。

### B4. 队列与用户控制

- 默认单路播放；手动新播报与自动播报的优先级有明确规则，旧内容可取消，队列有上限。
- 气泡提供播放/停止状态，设置提供试听；关闭气泡与是否停止朗读的关系需明确，并在两端一致。
- 对合成和播放设置超时，清理失败或取消后的临时资源。
- 将播放状态用于宠物情绪，完成或停止后恢复 idle，避免与现有恢复计时器冲突。

验收：连续触发不会声音重叠；静音、停止、失败和退出都能正确结束播放；临时文件不会持续累积。

### B5. 分阶段交付与测试

1. 先修正语音状态、错误返回和文本先展示，添加模拟引擎测试。
2. 接入 Windows 默认路径，完成安装后播放验收。
3. 接入 Android 原生路径，完成多设备生命周期验收。
4. 补齐试听、停止、队列、语速音量与设置热更新。

测试至少覆盖无引擎、无音色、断网、合成失败、播放器失败、用户取消、超长文本、开关关闭、快速重触发和应用退出。不通过模型/API Key 的成功来代替语音验收。

## 5. 阶段 C：设置与内容质量

- Android 补齐常规策略、采集平台、用户画像和语音界面，复用后端校验与密钥保留规则。
- 增加模型、向量模型、RSSHub 与语音引擎的独立测试入口，显示最近一次验证结果与时间。
- 区分“配置已保存”和“服务已验证可用”；无法热更新的项目明确标记重启要求。
- 去重从热点 ID 扩展到同一事件的跨平台归并，提供来源聚合，保留可追溯链接。
- 评估无真实向量时的匹配策略，避免把标题哈希占位向量描述为语义理解。
- 增加采集失败原因、可用来源、上次刷新时间等可读状态，避免用户只看到空结果。

验收：相同事件跨源出现时按约定归并；不支持 embeddings 的服务可单独关闭向量功能；用户能分辨网络、密钥、模型、平台和空候选问题。

## 6. 阶段 D：Android 后台与陪伴扩展

- 将“前台全屏”“后台持续运行”“跨应用悬浮宠物”“桌面组件”等模式分开设计，先明确用户需要的模式。
- 后台方案单独评估系统限制、权限、通知、功耗和生命周期，不以持续轮询代替可靠方案。
- 增加历史热点、手动重播、收藏、反馈撤销；重播应是用户显式操作，不能破坏当前防重复规则。
- 可选增加自由对话，但与事实热点播报区分，明确模型生成内容和来源信息。

验收：后台能力可由用户关闭，状态可见、耗电可评估；历史重播不会被当作新的联网新闻。

## 7. 阶段 E：资源与数据

- 宠物形象资源切换：校验尺寸、帧数、状态和透明背景，避免只改画像名称却误以为更换了形象。
- 配置、用户画像和宠物画像的导入导出与备份恢复；导出密钥需要单独明确选择。
- 优先评估系统凭据存储，减少配置文件明文密钥；分享日志前提供脱敏导出。
- 多设备同步作为明确开启的可选能力，先完成数据格式版本化与冲突处理，不默认上传本地数据。

验收：旧版本数据可迁移；导出文件有版本与校验；默认导出不包含密钥；导入失败不会破坏原数据。

## 8. 发布前统一验收

- Windows：干净环境安装、托盘/设置、长气泡滚动、模型与模板、双击联网刷新、升级保留数据。
- Android：全屏系统栏、固定主页面、气泡内滚动、双击无蓝色高亮、请求超时、返回前台行为。
- 语音：按阶段 B 的平台矩阵验证，不能仅凭编译通过宣布可用。
- 说明书、配置参考、已知问题、安装包版本同步更新。

开发执行时再拆分具体任务与估时；本计划不创建后台自动任务，也不自动安装依赖或发布程序。
