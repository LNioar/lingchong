# 模型请求与 Token 消耗说明

核对日期：2026-10-24。本文按当前源码说明请求来源与估算方法，替代旧版基于固定 0.6 门槛、工具调用概率和默认全天请求次数的预测。不提供实时价格或实际账单。

## 当前请求路径

| 请求 | 何时发生 | 缓存与重复请求边界 |
| --- | --- | --- |
| 热点标题 embeddings | 启用向量模型与 Key 时，采集批次处理标题 | 当前批次在去重判断前计算向量；重复采集不能一概视为零成本 |
| 兴趣主题 embeddings | Agent 处理候选时，对缺向量主题补算 | 成功后保存到画像；失败或结果数量不符时可能在后续周期重试 |
| 热点回复 chat | 自动筛选命中，或手动获取真实热点 | 当前 compose_script 不传 tools；输出为空或过渡语时可再请求一次，失败可降级模板 |
| 无热点回应 chat | 双击成功刷新但无可播报结果，或托盘手动入口无结果 | compose_idle_reply 不传 tools；当前无持久缓存，不可用时回退本地回应 |

依据：[采集管理](../crates/deskpet-collector/src/manager.rs)、[Agent 编排](../crates/deskpet-agent/src/orchestrator.rs)、[模型客户端](../crates/deskpet-agent/src/llm.rs)、[手动入口](../crates/deskpet-app/src/ipc.rs)。

未配置 Key 时 chat 方法在本地返回错误，由编排层使用模板，不发送对话 HTTP 请求。向量功能还要求配置非空向量模型名；关闭向量不代表同时关闭对话生成。手动召唤无新热点也可能发送 chat 请求，不能把“没显示新新闻”视为没有模型消耗。

## 不能再沿用的旧假设

- 自动播报不是所有情况都使用固定 0.6 门槛：无兴趣条目时为 0.3，有兴趣但没有可用向量时会将配置门槛乘 0.4；手动请求跳过自动门槛。
- 模型提示包含宠物和主人画像，回复长度由模型自由表达，不能固定按两句话或 60 tokens 计算。
- 当前热点和无热点回复都不携带工具定义，不能加上旧版“两个工具”和“30% function call”成本。
- 实际请求受前台运行时间、来源可用性、已播报记录、用户操作、重试、平台间隔与勿扰策略影响，不能仅凭默认间隔计算日账单。
- 空结果自然回应在手动刷新 45 秒计时之外；等待时间长短也不能直接换算为 token 用量。

## 估算方法

分别统计对话输入、对话输出与向量输入的 token 数，再按实际服务商、模型、缓存规则和计费单位计算：

```text
对话费用 = 输入 token 数 × 输入单价 + 输出 token 数 × 输出单价
向量费用 = 向量输入 token 数 × 向量单价
总费用 = 各模型实际计费项之和
```

上式单价须先换算到相同 token 单位。若有缓存命中、免费额度、批量优惠或失败计费规则，按服务商实际账单单独处理。当前代码没有完整的应用内 token 账单面板，不应将日志中的字符数当成实际 token 数。

排查消耗时先确认是否启用向量模型、一天实际运行多久、主动双击次数、热点回复重试次数和无热点回应次数。日志可能包含画像与请求正文，分享前应检查内容；最终用量以服务商 usage 和账单为准。
